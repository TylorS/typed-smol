# ADR: Runtime Cohesion Ownership Boundaries

Status: proposed

## Context

Typed is converging several parallel systems: headless UI primitives, compiled templates, resumability, Storybook virtual modules, Chrome DevTools tooling, and developer tooling across `vmc`, Vite, TS plugin, and VS Code. These systems must remain maintainable for at least five years.

The immediate remediation work needs a fully functional RealWorld example and end-to-end resumability, but the long-term risk is architectural drift: duplicating runtime handoff logic in Storybook, moving app policy into the compiler, pushing tooling host concerns into app runtime code, or letting UI primitives define private resumability conventions.

## Decision

Typed shall use package ownership boundaries that keep runtime policy, static analysis, tooling host integration, Storybook integration, and UI primitives separate.

### Package Ownership

- `@typed/template` owns template runtime contracts and low-level server/DOM template primitives.
  - It may define `DomTemplateRuntime`, `ServerTemplateRuntime`, compiled template shape, binding helpers, and boot helpers such as route/action resume scanning.
  - It must not know about `@typed/app`, Storybook, Chrome DevTools, app config, router registries, Vite, TS plugin, or VS Code.

- `@typed/compiler` owns static analysis, diagnostics, transformation, and generated code shape.
  - It may emit calls into `@typed/template` compiler-runtime helpers.
  - It may classify resumability and fail closed when route, template, event, or UI state cannot be made resumable.
  - It must not own browser runtime policy, app registry instances, Storybook runtime policy, or DevTools global installation.

- `@typed/app` owns app runtime composition.
  - It owns browser hydration, route/action resume registry composition, DevTools DOM observer wiring, and the browser global bridge used by Chrome DevTools.
  - It owns generated `typed:browser` runtime source.
  - It must not duplicate template binding logic, compiler analysis, or developer tooling host adapters.

- `@typed/storybook` owns Storybook framework integration.
  - It consumes `@typed/app` virtual modules and runtime helpers.
  - It may expose Storybook-specific decorators, renderers, runtime parameters, and portable story helpers.
  - It must not create a parallel browser runtime, parallel route/action resume registry, or parallel generated API client path.

- `@typed/ui` owns headless component primitives and public UI state conventions.
  - It owns RefSubject-backed state, Schema-backed `data-*` state, StartupRef hydration conventions, Collection/Composite behavior, and native Dialog/Popover-first layered widgets.
  - It must use public resumability conventions from compiler/app/template rather than private one-off component hydration paths.

- Developer tooling owns host integration.
  - `@typed/virtual-modules-*`, `@typed/vite-plugin`, TS plugin, VS Code integration, `vmc`, virtual-id hygiene, and host diagnostics belong to the developer-tooling workflow.
  - Runtime remediation must not edit those surfaces without explicit handoff.

### Cross-System Rules

- There is one browser runtime handoff path: `typed:browser` source generated by `@typed/app` creates an app DOM runtime and passes it into compiled templates.
- There is one route/action resume runtime path: app-owned registries are composed into `DomTemplateRuntime`.
- There is one DOM DevTools bridge path: `@typed/app/runtime` installs the browser bridge expected by `@typed/devtools-chrome`; `@typed/devtools-runtime` remains the registry/event substrate.
- Storybook must exercise the same generated runtime path used by applications.
- RealWorld is the flagship compliance fixture. Passing package unit tests is insufficient if RealWorld functional, compliance, or resumability gates fail.

## Design Principles

- DRY: do not duplicate runtime handoff, registry setup, DevTools bridge installation, route/action resume scanning, or generated client logic.
- SOLID: each package has one reason to change; consumers depend on stable contracts, not package internals.
- YAGNI: do not add generic plugin systems, alternate runtimes, or adapter layers unless the RealWorld gates or developer-tooling handoff prove they are required.
- Fail closed: non-resumable code must produce a diagnostic or a failing gate, not silently fall back to behavior that appears resumable.
- Virtual-module first: do not introduce filesystem routing or local `declare module "typed:*"` shims as a workaround for generated surfaces.

## Consequences

- Runtime fixes should primarily touch `@typed/app`, `@typed/template` contracts, and narrowly-scoped compiler emission.
- Storybook fixes should stay adapter-level and should not fork app hydration behavior.
- RealWorld warnings about server code in browser bundles are architecture signals until proven harmless.
- Developer tooling work remains independently ownable by the active tooling agent.
- Future maintainers can audit a change by asking which package owns the reason for change.

## Alternatives Considered

- Put resumability composition in `@typed/template`: rejected because template runtime contracts should not own app registries, DevTools globals, or browser policy.
- Put resumability composition in `@typed/compiler`: rejected because generated code shape and runtime instance policy are different reasons to change.
- Let Storybook own a specialized runtime: rejected because it duplicates app behavior and weakens RealWorld as the integration fixture.
- Fold developer tooling fixes into runtime remediation: rejected unless required by RealWorld gates and explicitly handed off, because the tooling workflow is active under another agent.
